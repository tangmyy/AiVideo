# B 站与抖音链接下载设计

## 目标

用户粘贴单条视频链接后，程序识别 B 站或抖音，查询该视频实际可用的画质。用户选定画质后才开始下载，并能看到状态、进度、错误及保存位置。

## 范围

- 支持 B 站 BV 号、作品链接，以及抖音作品链接和含短链的分享文案。
- 一个“查询视频”按钮同时查询平台、标题、封面和可用画质；查询成功前禁用下载按钮。封面无法取得时显示占位图和说明，不影响可用画质的选择。
- 画质列表来自该视频实际返回的流，不展示无法下载的固定档位。若同一分辨率有多个编码或码率，界面给出可区分的标签。
- 下载阶段锁定当前链接与画质，后台执行下载。仅在媒体下载、必要的合并或转换及文件保存全部成功后显示完成。
- 保留现有 B 站下载能力，并修正其画质选项未生效、进度提前显示完成的问题。

## 不包括

批量下载、主页或合集下载、私密内容、去水印承诺。平台返回的画质和访问限制以实际解析结果为准。

抖音提取器若要求新的 Cookie，用户可在界面主动选择 Chrome、Edge、Firefox 或 Netscape 格式 Cookie 文件，再重新查询。默认不读取浏览器 Cookie；所选来源仅在本次运行中使用。即使提供 Cookie，站点接口变化仍可能阻止解析。

## 方案比较

1. **B 站沿用 `bilibili-api-python`，抖音使用 `yt-dlp`（选定）**：保留现有 B 站逻辑，分别查询两端格式，再统一界面状态。改动较小，但需处理两套下载器的进度和错误。
2. 两站都改用 `yt-dlp`：接口较统一，但会替换当前 B 站实现，并引入额外回归风险。
3. 自行解析抖音网页与媒体地址：依赖站点内部结构，维护成本高。

## 界面与流程

```text
┌──────────────────────────────────────────────────────┐
│ AiVideo                                  视频下载工作台 │
│ 粘贴 B 站或抖音视频链接 / 分享文案           [查询视频] │
├──────────────────┬───────────────────────────────────┤
│                  │ 平台 · 视频标题                      │
│     视频封面     │ 可用画质 [实际可用选项 ▼]            │
│                  │ 保存到   [目录路径] [选择目录]       │
│                  │                    [开始下载]       │
├──────────────────┴───────────────────────────────────┤
│ 状态：查询中 / 下载中 / 处理中 / 完成或失败   [进度条] │
└──────────────────────────────────────────────────────┘
```

视觉方向采用轻量的深色工具台：清晰的大标题、柔和的背景层次、醒目的单一强调色、宽松间距和明确的按钮状态。布局随窗口宽度调整，窄窗口时封面与信息上下排列。保留 PyQt5 技术栈，用 QSS 实现样式，并确保文字对比度、键盘操作和长标题截断可用。

输入变更后清除旧查询结果并禁用下载。点击唯一的查询按钮后，封面与画质在同一任务中获取；查询和下载都在后台运行，界面保持响应。选择的画质以查询时返回的格式标识为准，下载时不静默改成别的画质；若资源失效或受限，提示重新查询或具体错误。完成后显示最终文件路径。

## 约束与验证

本项目是 PyQt5 桌面程序，以 `aivideo_gui.py` 为当前 README 指定入口。优先复用项目内 FFmpeg。验证包括链接识别、画质列表与选择、查询失败、下载成功与失败、界面不阻塞，以及 FFmpeg 合并完成后才提示成功。抖音解析能力需以可访问的真实公开视频链接实测，不能仅凭支持列表保证。
